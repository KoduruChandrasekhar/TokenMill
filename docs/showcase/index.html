The tie that HF breaks both ways

fp32 golden test

One golden prompt diverged at token 11 in every engine configuration. The top two logits there differ by 9.5e-6, and HuggingFace disagrees with itself: its incremental generate() picks one token, its own full forward pass the other. The test now records each position's top-2 gap and allows a divergence only at a recorded tie.

fp16 that was fp32

found by a 30-minute GPU probe

The loader built the model on the meta device in fp32 and copied the fp16 weights into fp32 parameters, so --dtype float16 silently ran in fp32. Only the GPU showed it, as a dtype crash in static batching; a CPU test that loads in half precision guards it now.

3 tok/s that was 37

load generator

When a one-user run hit its 15-minute cap, requests still queued had a send time of 0, which stretched the measured duration back to the clock's origin and marked the run saturated, skipping the higher-concurrency points. Found because the number disagreed with the server's own metrics.

A soak test that cancelled itself

30 minutes at 4 req/s

602 of 6,600 requests "failed", about 20 a minute, while GPU memory and free blocks were identical at every idle point. Each round sent 55 seconds of arrivals and cut itself off at 55 seconds. Fixed, the rerun completed every request.

Graph numbers that were eager numbers

CUDA graphs, part 4

128 finer-bucket graphs ran out of memory next to a KV pool sized at 90% of the GPU. The engine fell back to eager decoding as designed, and the "graph" runs matched eager within 1%, which is how it showed. Graph memory is now set aside before the pool is sized.

Method: Poisson arrivals at 1 to 32 requests per second plus all at once, and closed-loop runs with 1, 8, 32 and 128 users in flight; 20 warm-up requests discarded; three runs per point; output lengths forced with ignore_eos so every server generates the same tokens. TTFT is time to first token, TPOT is time per output token after the first.
